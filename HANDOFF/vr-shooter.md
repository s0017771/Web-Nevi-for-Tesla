# 🏹 VR 석궁 (vr-shooter.html) — 작업 지침

> 먼저 `HANDOFF/CONTEXT.md`를 읽을 것. 목표 완성도 **70%까지 올린 뒤 사용자에게 먼저 보여주고**, 검증 후 계속.

## 콘셉트
중력 포물선 + 바람의 영향을 받는 물리 석궁. 꾹 당겨(충전) 떼면 발사(오래 당길수록 멀리). VR(컨트롤러)과 모바일(폰 자이로) 두 모드. 연습(단계)과 대전(AI) 모드.

## 현재 상태(대략 55%, 이미 구현된 것)
- **모드 선택**: 시작 화면에서 🥽 VR / 📱 모바일 토글 + [연습] [대전] 버튼. 모바일 UA 자동 추정.
- **충전식 발사**: `__drawStart`(누름)→`__drawPower()`(0~1, DRAW_MS=1200ms)→`__drawRelease(sx,sy,sz,dx,dy,dz)`. 속도 `speedFor(pw)=16~38`. 당기는 동안 시위가 뒤로 당겨짐, 파워바(HTML) 표시.
- **VR**: 양손 `bow`(mount:hand) 컴포넌트, triggerdown=당기기 / triggerup=발사(컨트롤러 전방).
- **모바일**: 카메라에 석궁 장착(`cambow`, bow mount:camera), 자이로 조준(`look-controls magicWindow, touchEnabled:false`), 꾹 눌러 당기고 떼면 카메라 전방으로 발사(직접 mousedown/touchstart↔up 핸들), **🎯 중앙정렬** HTML 버튼(`recenter()`: rig yaw 보정), 화면 중앙 크로스헤어.
- **물리**: `bolt` 컴포넌트 — `v.y += -grav*k; v.x+=wind.x*k; v.z+=wind.z*k; p+=v*k` (grav=9.8). 궤적 트레일. 과녁 충돌 `dist < r+0.09`.
- **연습 1~20단계**: 1~10 근거리(기존), **11~20 원거리**(`makeTarget`에서 `far=L>10`: 거리 18→~60m, 물리크기 키워 각크기 유지, 거리 라벨 표시). 화살 제한(소진 시 실패).
- **대전 모드**: `setupDuel` — 상대 과녁(46m) + 상대 궁수 + 내 과녁(옆). `ballisticAim(S,T,v,g)`로 AI가 내 과녁을 물리적으로 조준(라운드 갈수록 정확). 먼저 상대 과녁 맞추면 승(`duelWin`), 내 과녁 맞으면 패(`duelLose`).
- **휘익 사운드**: `__startWhoosh/__updWhoosh/__stopWhoosh` — incoming(AI) 볼트가 카메라에 접근할수록 루프 노이즈 밴드패스 볼륨/피치 상승(doppler 느낌).
- 테스트 훅: `window.__CROSSBOW_TEST__` (startPractice, startDuel, ballisticAim, speedFor, loadLevel, fireAt, aiShoot …).

## 반드시 해결할 것 (알려진 미완/버그)
1. **대전 턴 전환 미완**: 플레이어가 쐈는데 **빗나가면** AI 턴으로 넘어가는 배선이 없음(`__afterPlayerShot`은 정의만 됨, 호출 안 됨). → 플레이어 볼트가 과녁을 못 맞히고 소멸할 때를 감지해 `aiTurn()` 호출. (bolt `kill()`에서 owner='me'·명중 안 함이면 콜백, 또는 발사 후 일정 시간 내 미명중이면 AI 턴.) 한 발씩 주고받는 흐름 완성.
2. **모바일 자이로/권한**: iOS는 deviceorientation 권한 필요(`device-orientation-permission-ui` 켜둠). 실기기에서 자이로 조준·중앙정렬 동작 확인·보정 필요(코드로 검증 불가).
3. **발사 방향 정밀도**: 모바일은 카메라 전방으로 발사 → 조준점(크로스헤어)과 실제 탄착 일치하는지, 충전 파워에 따른 낙차 보정 안내(겨냥선/예상 궤적 가이드) 고려.

## 사용자가 요청한 목표(70%까지)
1. **모바일 터치 완성**(화면회전 터치 불필요, 중앙정렬 버튼, 화면중앙 석궁, 꾹 당겨 떼서 발사). ✅ 기반 구현됨 — 실기기 검증·다듬기 필요.
2. **원거리 과녁(레벨 11+)**. ✅ 기반 구현됨 — 거리감/난이도 밸런스·조준 보조 다듬기.
3. **대전 모드**(아주 먼 상대 과녁, 한 발씩, 물리 화살, 먼저 맞추면 승, 사람은 안 맞음, 접근 화살 리얼 사운드). ✅ 기반 구현됨 — 턴 전환(위 1) 완성 + 사운드/밸런스 다듬기.
4. **에이전트로 검증 후 70%까지 수정**:
   - **물리 검증**: 탄도(포물선·중력·바람 드리프트)가 해석적 포물선과 일치하는지(헤드리스 적분 vs 공식). `ballisticAim`이 실제로 과녁에 떨어지는지 시뮬레이션.
   - **사운드 검증**: OfflineAudioContext로 휘익/트윙/명중음 렌더 분석(접근 시 볼륨·피치 상승, 클리핑 없음).
   - **비주얼 검증(2D 반실사)**: 과녁/석궁/화살/풍경이 반실사 느낌인지(기기 스크린샷은 사용자). 코드 리뷰로 색/깊이/안개/그림자 개선안.
   - **모바일 + VR 양쪽 검증**: 입력 경로(충전/발사/조준) 로직 분기 확인.
   - 여러 에이전트를 병렬로 두고, 각자 구체적 증거(수치/시뮬레이션 결과)를 내게 하고, 발견된 문제를 수정.
5. **70% 도달 시 먼저 사용자에게 보고**하고, 사용자 검증 후 계속 완성도 상승.

## 검증 방법(참고)
- 물리: 헤드리스에서 `bolt` 적분 로직을 떼어내 순수 함수로 시뮬레이션하거나, `__CROSSBOW_TEST__`에 궤적 덤프 훅 추가. 공식: 사거리 `R=v²sin(2θ)/g`, 최고점 등으로 교차검증.
- 탄도 해법 단위테스트: `ballisticAim`이 준 벡터로 적분하면 목표에 도달해야 함(오차 수 cm).
- A-Frame abort 헤드리스 + `__CROSSBOW_TEST__` 훅으로 상태/점수/턴 검증.
- 에이전트에게는 "결론이 아니라 증거(수치)"를 요구하고, 내 가설을 주지 말 것.
